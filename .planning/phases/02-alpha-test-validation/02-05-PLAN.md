# Phase 2 Plan 05: Monitor Google Ads Detection (4-Week Alpha Test)

**Requirement Coverage:** ALPHA-02 (Monitor Google Ads detection over 4-week period; track days-to-flag per domain)

**Objective:** Execute daily monitoring of all 5-10 deployed test domains to track Google Ads account status changes (flags, suspensions, bid reductions). Measure days-to-flag baseline and capture detection timeline distribution across fingerprinting vectors.

**Prerequisite:** Phase 2 Plan 04 (5-10 domains deployed with baseline metrics recorded) must be complete.

---

## Tasks

### Task 1: Implement Daily Monitoring Script

**Objective:** Create automated monitoring pipeline to check Google Ads account status for each test domain daily.

**Acceptance Criteria:**
- [ ] Create `scripts/alpha-monitor.js` that:
  - Reads deployment manifest (`.planning/alpha-test/deployments.json`)
  - For each domain:
    - Fetch Google Ads account status via Google Ads API (or management dashboard if API unavailable)
    - Record status snapshot: account_status, bid_status, policy_violation_count
    - Compare against previous day's snapshot
    - Detect state changes: `active` → `flagged`, `flagged` → `suspended`, etc.
    - Log timestamp, domain, status, change_type (if any)
  - Persist results to `.planning/alpha-test/daily-monitoring.jsonl` (one JSON line per domain per day)
  - Return summary: domains_checked, status_changes_detected, errors
- [ ] Implement error handling for API rate limits, authentication failures, network timeouts
- [ ] Support manual re-run for specific date range (backfill missing days)
- [ ] Implement optional verbose logging mode for debugging API responses
- [ ] Document prerequisites: Google Ads API credentials, rate limit strategy (batch calls, exponential backoff)

**Success Metric:** Monitoring script functional and tested on 1-2 live domains; ready for 4-week continuous execution

**Read First:**
- `.planning/alpha-test/deployments.json` (created in Plan 04)
- Google Ads API documentation (account service, policy manager)

---

### Task 2: Set Up Alerting & Change Detection

**Objective:** Capture detection events and flag anomalies in real-time for immediate response.

**Acceptance Criteria:**
- [ ] Implement change detection in `scripts/alpha-monitor.js`:
  - Compare current status against baseline (from `.planning/alpha-test/baseline-metrics.json`)
  - Flag status transitions: `active` → `flagged`, `active` → `suspended`, `flagged` → `suspended`
  - Record days-since-deployment when change detected (e.g., "flagged on day 5")
  - Classify change severity: critical (suspension), medium (flag), low (bid adjustment)
- [ ] Create `.planning/alpha-test/detection-events.json` manifest:
  - `domainId`: test domain identifier
  - `detectedAt`: ISO timestamp when status change detected
  - `daysToFlag`: integer (days from deployment to detection)
  - `initialStatus`: status at deployment time
  - `detectedStatus`: status after change
  - `severity`: critical|medium|low
  - `cause`: suspected reason (policy violation, manual review, behavioral pattern, etc.)
- [ ] Optional: Create webhook endpoint (or Slack integration) to notify on detection events
  - POST to external service with event summary
  - Include domain ID, days-to-flag, severity
  - Enable real-time monitoring of test progress
- [ ] Document alert escalation process (if critical detection occurs early)

**Success Metric:** Change detection tested on mock data; alerts functional for 1-2 domains; ready for continuous 4-week monitoring

**Read First:**
- Google Ads API policy_manager documentation (flag reasons)
- `.planning/alpha-test/baseline-metrics.json` (comparison baseline)

### Task 3: Execute Continuous 4-Week Monitoring Period

**Objective:** Run daily monitoring script for 4 weeks without gaps to capture full detection timeline.

**Acceptance Criteria:**
- [ ] Schedule monitoring via cron or persistent task scheduler:
  - Daily execution at fixed time (e.g., 00:00 UTC or 9am local)
  - Retry on failure with exponential backoff (1min, 5min, 30min, 2hr max)
  - Log all executions (start, end, success/failure, row count)
- [ ] Monitor script health:
  - Alert if daily run misses 2 consecutive days
  - Alert if error rate >10% of domains per day
  - Track API rate limit consumption (warn if >80% of daily quota)
- [ ] Record continuous metrics:
  - `daily-monitoring.jsonl`: append one JSON line per domain per day (5-10 domains × 28 days = 140-280 rows minimum)
  - Maintain `detection-events.json`: update in real-time when status changes detected
  - Log file: `alpha-monitoring.log` (timestamp, script run ID, success count, errors)
- [ ] Mid-test checkpoint (day 14):
  - Analyze 2-week data
  - Check for early detection patterns
  - Assess monitoring health (any domains already flagged? Rate of flags?)
  - Document observations in `.planning/alpha-test/CHECKPOINT-14DAY.md`
- [ ] Final verification (day 28):
  - All 5-10 domains monitored for full 28 days
  - Detection timeline captured for early-detected domains
  - Final status recorded for undetected domains (still active or already flagged)

**Success Metric:** 4-week continuous monitoring completed; all domains tracked; detection events recorded with timestamps

**Read First:**
- `scripts/alpha-monitor.js` (from Task 1)
- System scheduler documentation (cron, Windows Task Scheduler, systemd timers)

### Task 4: Compile Monitoring Data & Detection Timeline Report

**Objective:** Aggregate 4-week monitoring data and analyze detection patterns.

**Acceptance Criteria:**
- [ ] Create `scripts/alpha-consolidate-monitoring.js` that:
  - Reads all daily snapshots from `daily-monitoring.jsonl`
  - Aggregates by domain: status timeline, status change events, days-to-flag
  - Detects patterns: which domains flagged early vs. late, any suspended domains, still-active domains
  - Calculate statistics:
    - Mean days-to-flag across all detected domains
    - Median days-to-flag
    - Std dev and range (min/max days-to-flag)
    - Count of domains: still active, flagged, suspended
  - Output: `.planning/alpha-test/monitoring-summary.json` with per-domain and aggregate stats
- [ ] Generate monitoring report: `.planning/alpha-test/MONITORING-REPORT.md`
  - Executive summary: "Of 10 domains deployed, X flagged after avg Y days, Z still active"
  - Per-domain timeline table:
    | Domain | Template | Deployed | Flagged | Days-to-Flag | Final Status |
    |--------|----------|----------|---------|--------------|--------------|
    | alpha-astro-001 | Astro | 2026-03-21 | 2026-03-31 | 10 | Suspended |
    | alpha-vite-react-001 | React | 2026-03-21 | None | — | Active |
  - Detection timeline visualization (day 1-28 with X-axis, count of daily flags on Y-axis)
  - Notes on patterns: template type correlation? Fingerprinting vector effectiveness?
  - Severity distribution: count of critical/medium/low detections per domain type
- [ ] Validate data completeness:
  - Confirm all 5-10 domains have 28 days of monitoring data
  - Identify any gaps and note reasons (API downtime, script failure, etc.)
  - Flag suspect data (e.g., status changed multiple times in one day = API inconsistency?)

**Success Metric:** Monitoring data consolidated; report generated; statistics validated; ready for Phase 3 analysis

**Read First:**
- `daily-monitoring.jsonl` (4-week collected data)
- `detection-events.json` (status change events)
- `.planning/alpha-test/CHECKPOINT-14DAY.md` (mid-test observations)

## Notes

- **API Rate Limits:** Google Ads API allows ~10,000 operations/day. Batch 5-10 domains into single API call (~100 ops/day), leaving 99% margin.
- **Detection Timeline Baseline:** Establish "detection = 0 before deployment" to ensure early detection signals aren't baseline noise (ALPHA-01 baseline metrics establish this).
- **Fingerprinting Vector Correlation:** Plan 05 data feeds Plan 06 analysis — expect correlation between deployed fingerprinting vectors (class name, ID, data attribute, aria label, meta tag, structural) and detection timeline.
- **Still-Active Domains:** Domains never detected are highest priority for next Phase 3 analysis — which vectors drove successful evasion?
- **Suspended vs. Flagged:** Suspension (account freeze) vs. flagged (restrictions) may indicate different detection mechanisms — track separately.
