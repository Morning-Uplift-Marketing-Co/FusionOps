# Phase 2 Plan 04: Deploy 5-10 Test Domains with Anti-Fingerprinting

**Requirement Coverage:** ALPHA-01 (Deploy 5-10 test domains with randomized fingerprinting)

**Objective:** Deploy a statistically significant sample (5-10 domains) across diverse template formats (Astro, Vite/React, static HTML) to distinct Cloudflare Pages deployments, each with unique deterministic fingerprinting applied. Establish baseline metrics for alpha test.

**Prerequisite:** Phase 2 Plans 01-03 (multi-format build infrastructure, anti-fingerprinting service, integration tests) must be complete and passing.

---

## Tasks

### Task 1: Generate Test Domain Configuration (5-10 domains)

**Objective:** Create alpha test domain manifest with siteId, template type, and randomization seed for each domain.

**Acceptance Criteria:**
- [ ] Create `.planning/alpha-test/domains.json` with 5-10 test domains, each with:
  - `siteId`: Unique identifier (e.g., "alpha-astro-001", "alpha-vite-react-001", "alpha-html-001")
  - `template`: Template type (astro, vite-react, static-html)
  - `cloudflareProject`: CF Pages project name (auto-derived)
  - `seed`: Deterministic seed for fingerprinting (SHA256 derived from siteId)
  - `deploymentDate`: ISO timestamp for tracking
  - `status`: "pending" (initial state)
- [ ] Ensure diversity across formats: minimum 2 Astro, 2 Vite/React, 2 static HTML (11 total if possible for statistical confidence)
- [ ] Document randomization vectors applied per domain (CSS classes, IDs, data attributes, aria labels, meta tags, structural variation)
- [ ] Include cost estimation: Cloudflare Pages free tier + estimated tracking pixel costs

**Success Metric:** domains.json validated; 5-10 domains ready for deployment

**Read First:**
- `.planning/STATE.md` (architecture context)
- `src/services/AntiFingerprint.js` (fingerprinting strategies)
- `src/utils/fingerprint-seeder.js` (seeding mechanism)

---

### Task 2: Prepare Build & Deploy Automation

**Objective:** Set up one-shot deployment scripts to build each domain with fingerprinting and push to Cloudflare Pages.

**Acceptance Criteria:**
- [ ] Create `scripts/alpha-deploy.js` that:
  - Reads domains.json
  - For each domain:
    - Load wizard configuration (brand, colors, tracking setup)
    - Run `TemplateBuilder.build()` (Phase 2 Plan 01)
    - Run `AntiFingerprint.transform()` (Phase 2 Plan 02) with deterministic siteId seed
    - Deploy to Cloudflare Pages via API
    - Log deployment URL and fingerprinting seed to deployment manifest
  - Return deployment status (success/failure) per domain
- [ ] Create `scripts/alpha-verify-deployment.js` to validate each deployed domain:
  - Fetch deployed HTML
  - Verify randomized class names are present
  - Verify tracking pixels (Voluum, Google Ads) are intact
  - Verify no Astro expressions leaked (`import.meta.env.PUBLIC_*`)
- [ ] Document deployment procedure: setup, prerequisites, error handling
- [ ] Test with 1-2 domains in staging before full batch

**Success Metric:** Deploy scripts functional and tested on staging domains; ready for production batch

**Read First:**
- `.planning/phases/02-multi-format-build-anti-fingerprint-pipeline/02-01-PLAN.md` (TemplateBuilder orchestration)
- `.planning/phases/02-multi-format-build-anti-fingerprint-pipeline/02-02-PLAN.md` (AntiFingerprint.transform API)
- Cloudflare Pages API documentation

---

### Task 3: Deploy 5-10 Test Domains

**Objective:** Execute batch deployment of all 5-10 test domains using automation scripts.

**Acceptance Criteria:**
- [ ] Deploy all 5-10 domains to distinct Cloudflare Pages projects
- [ ] Verify each deployment:
  - HTML loads without errors
  - Fingerprinted CSS classes present (e.g., `fp-abc123`)
  - Tracking pixels firing (check Network tab or monitoring service)
  - No Astro env expression leaks (QUAL-03 validates this)
  - Mobile + desktop viewports responsive (no layout breaks)
- [ ] Create `.planning/alpha-test/deployments.json` manifest with:
  - `siteId`: Domain identifier
  - `url`: Cloudflare Pages URL (https://...)
  - `deployedAt`: ISO timestamp
  - `template`: Template type deployed
  - `fingerprint`: Seed used for randomization
  - `status`: "deployed"
  - `qaCheckpoint`: {viewport_ok, tracking_ok, leaks_none, responsive_ok}
- [ ] Document any deployment failures (retry count, error message, resolution)

**Success Metric:** 5-10 domains deployed, each passing QA checkpoint

**Read First:**
- `scripts/alpha-deploy.js` (created in Task 2)
- `scripts/alpha-verify-deployment.js` (created in Task 2)

---

### Task 4: Record Initial Baseline Metrics

**Objective:** Capture initial state of each deployed domain for comparison during monitoring phase (Plan 05).

**Acceptance Criteria:**
- [ ] For each domain, capture baseline:
  - `pageLoadTime`: Lighthouse API (or advisory if unavailable) - should be 90+
  - `pageSize`: Deployed HTML size (bytes)
  - `requestCount`: Number of network requests
  - `trackedPixels`: Count of firing tracking pixels (Voluum + Google Ads)
  - `googleAdsStatus`: Account status (active, flagged, suspended) via Google Ads API
  - `domainAge`: WHOIS age (if applicable)
  - `timestamp`: ISO baseline timestamp
- [ ] Store baseline in `.planning/alpha-test/baseline-metrics.json`
- [ ] Generate baseline report: `.planning/alpha-test/BASELINE-REPORT.md`
  - Show per-domain baseline snapshot
  - Aggregate statistics (avg load time, avg page size, etc.)
  - Note any red flags at baseline (e.g., Google Ads already flagged)

**Success Metric:** Baseline metrics collected for all 5-10 domains; report generated

**Read First:**
- Google Lighthouse API documentation
- Google Ads API documentation (account status checks)

## Notes

- **Cost:** Cloudflare Pages free tier covers unlimited deployments. Monitor tracking pixel costs (Voluum, Google Ads) for 10 domains × 4 weeks.
- **Fingerprinting Determinism:** SHA256(siteId) → seedrandom ensures byte-identical output on redeploy, enabling clean A/B testing with same fingerprint.
- **QA Checkpoint:** Task 3 validation gate prevents moving to monitoring phase with broken deployments.
- **Baseline Importance:** Establishes detection timeline "zero" — any Google Ads activity before baseline timestamp is anomaly, not detection signal.
