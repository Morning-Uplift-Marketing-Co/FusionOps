Output: Three utility modules with test coverage demonstrating: manifest loading, auto-detection with scoring, and priority-based resolution.

Create `src/utils/capability-detector.js` that:
1. Exports `autoDetectCapabilities(files)` → returns capabilities object
2. Detect 5 capabilities using signal-based scoring (see 01-RESEARCH.md "Pattern 3: Multi-Level Capability Detection"):
   - `supportsCalculator`: Find Calculator component, range inputs, Math.min/max, loan amount variables
   - `supportsSectionReorder`: Count sections, find dynamic spreading ([...sections]), flexible layouts
   - `supportsFormCustomization`: Find form elements, input fields, action handlers
   - `supportsCustomColors`: Find CSS variables (--color-*, --primary), hsl/rgb colors, color props
   - `supportsImageUpload`: Find image upload components, file input handling
3. For each capability:
   - Weight each signal (0.1-0.4 range)
   - Score = matched_weight / total_weight
   - Confidence threshold: >= 0.65 enables feature, < 0.65 disables
   - Return: { value: boolean, confidence: number (0-1), reason: string }
4. Reuse file search helpers from template-analyzer.js

Create test file `src/utils/__tests__/capability-detector.test.js`:

- Test 3: Confidence scoring: 80% matched signals → confidence 0.80
- Test 4: Confidence >= 0.65 enables feature; < 0.65 disables
- Test 5: Detect custom colors from CSS variables
- Test 6: Detect form from form element
- Test 7: Multiple templates show different capability profiles

Use realistic sample files: sections with HTML, component names, variable names from research docs.

Create `src/utils/capability-resolver.js` that:
1. Exports `resolveCapabilities(files, manifest, userOverride = {})` → returns capabilities object
2. Resolution priority (Level 1 wins if present, else try Level 2, etc.):
   - Level 1 (Manifest): If manifest exists and manifest.capabilities exists, use manifest capabilities exclusively
   - Level 2 (Auto-detect): If no manifest, call autoDetectCapabilities(files)
   - Level 3 (User Override): Merge userOverride into capabilities, setting confidence to 1.0 for overridden values
3. Return merged capabilities object where each capability has: value, confidence, reason, autoDetected (boolean)
4. Overridden capabilities should have reason: "User-overridden in wizard" and confidence: 1.0

Create test file `src/utils/__tests__/capability-resolver.test.js`:

- Test 4: Multiple overrides applied correctly
- Test 5: Override for capability that doesn't exist in base → ignored gracefully
- Test 6: Manifest + override → manifest wins (override doesn't override manifest)
- Test 7: Full flow: template → detect → override → verify priority order

Each test verifies priority chain explicitly.
