## v1.1 Requirements — Phase Breakdown

### Phase 1: Live Template Preview (PREV-01–04)

**Goal:** Enable operators to preview templates with injected variables before deployment, with multi-viewport support and fingerprinting diagnostics.

- [x] **PREV-01**: Live preview renders template in iframe with injected variables
  - **Acceptance:** Modal opens in Wizard Step 5 (Review); shows template HTML in iframe with site-specific brand name, color, copy injected
  - **Validation:** Preview renders Astro, Vite/React, and static HTML templates without errors
  - **Phase:** 1

- [x] **PREV-02**: Mobile/desktop viewport toggle in preview modal
  - **Acceptance:** Preview shows 320px (mobile) and 1024px (desktop) viewport options; toggle switches without re-rendering template
  - **Validation:** Both viewports display correctly; mobile shows stacked layout, desktop shows full layout
  - **Phase:** 1

- [x] **PREV-03**: Real-time variable preview (change brand name → preview updates)
  - **Acceptance:** Preview refreshes within <1s when user changes brand name, color, or copy in prior wizard steps
  - **Validation:** Debounced refresh; no console errors; variable injection accurate
  - **Phase:** 1

- [x] **PREV-04**: Preview shows both pre-fingerprint and post-fingerprint versions
  - **Acceptance:** Toggle in preview modal switches between original HTML and randomized HTML; side-by-side or tab comparison
  - **Validation:** Pre-fingerprint shows unmodified template; post-fingerprint shows CSS class changes, ID randomization, meta tag variation
  - **Phase:** 1

---

### Phase 2: Alpha Test Validation (ALPHA-01–03)

**Goal:** Deploy 5-10 test domains with the complete v1.0 pipeline and measure anti-fingerprinting effectiveness against Google Ads detection systems.

- [x] **ALPHA-01**: Deploy 5-10 test domains with randomized fingerprinting across all vectors
  - **Acceptance:** Deploy test suite of Astro, Vite/React, and static HTML templates to distinct Cloudflare Pages domains
  - **Validation:** All 5-10 domains deploy successfully; each with unique CSS class names, IDs, and meta tags
  - **Phase:** 2

- [x] **ALPHA-02**: Monitor Google Ads system detection over 4-week period
  - **Acceptance:** Track days-to-flag for each test domain; document Google Ads behavior (account flags, domain suspension, etc.)
  - **Validation:** Collect data on detection timeline (targets: 10+ days undetected as stretch goal)
  - **Phase:** 2

- [x] **ALPHA-03**: Document findings and gaps in randomization strategy
  - **Acceptance:** Create ALPHA-FINDINGS.md report with detection patterns, gaps, and recommendations for v1.2
  - **Validation:** Report identifies if HTML/CSS randomization alone is sufficient or additional vectors needed (behavioral, registrant, traffic patterns)
  - **Phase:** 2

---

### Phase 3: Performance Optimization (PERF-01–02)

**Goal:** Benchmark build pipeline at scale (20, 40, 50+ concurrent deployments) and implement queue if needed.

- [x] **PERF-01**: Benchmark build isolation memory usage at concurrent scales
  - **Acceptance:** Run stress test with 20, 40, 50+ concurrent template builds; measure peak RAM, CPU, build time per template
  - **Validation:** Document memory usage per format (Astro, Vite, HTML); identify bottlenecks
  - **Phase:** 3

- [x] **PERF-02**: Implement build queue if peak memory exceeds 90% threshold
  - **Acceptance:** If stress test shows >90% RAM at 50+ concurrent, implement queue system with configurable concurrency limit
  - **Validation:** Queue system tested; peak memory <80%; deploy time degradation acceptable (<2x)
  - **Phase:** 3

## Deferred from v1.0

All 4 PREV-* requirements were deferred from v1.0 Phase 4:
- PREV-01: Live preview iframe rendering
- PREV-02: Viewport toggle
- PREV-03: Real-time preview refresh
- PREV-04: Pre/post-fingerprint comparison

**Rationale:** v1.0 core pipeline (import, build, fingerprint, quality checks) complete and production-ready. Phase 4 is UX enhancement that doesn't affect deployment reliability. Deferred to v1.1 for polish cycle post-production validation.
