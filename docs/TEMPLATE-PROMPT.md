# AI Template Generation Prompt

Copy the relevant section below and paste into Bolt.new, Lovable, or any AI IDE when creating a new landing page template.

---

## Prompt for Bolt.new / Lovable / v0

```
Create a loan affiliate landing page with Astro 4 + Tailwind CSS.

=== WHAT YOU NEED TO BUILD ===

Only the LANDING PAGE (index.astro). The build system handles tracking, apply page, and color switching automatically. You do NOT need to write any tracking code.

=== STRUCTURE ===

Required files:
- package.json (with astro, @astrojs/tailwind, tailwindcss)
- astro.config.mjs (output: 'static')
- tsconfig.json
- src/pages/index.astro (main landing page — THIS IS YOUR FOCUS)
- src/layouts/Layout.astro (base HTML shell)
- src/styles/global.css (with @tailwind directives + CSS vars)

NOT needed (auto-generated by build pipeline):
- src/pages/apply.astro — BUILD PIPELINE GENERATES THIS
- Tracking scripts — BUILD PIPELINE INJECTS THESE
- Voluum/pixel code — BUILD PIPELINE INJECTS THESE

=== COLOR SYSTEM (CRITICAL) ===

DO NOT hardcode colors like bg-orange-500 or text-blue-600.
ALWAYS use CSS variable-based classes:

GOOD:
  bg-primary          (maps to --primary CSS var)
  text-primary        (maps to --primary CSS var)
  bg-secondary        (maps to --secondary CSS var)
  text-accent         (maps to --accent CSS var)
  bg-background       (maps to --background CSS var)
  text-foreground     (maps to --foreground CSS var)
  border-primary
  ring-primary
  hover:bg-primary/90

BAD:
  bg-orange-500       (hardcoded — cannot change)
  text-blue-600       (hardcoded — cannot change)
  bg-emerald-100      (hardcoded — cannot change)

For lighter/darker shades, use opacity:
  bg-primary/10       (10% opacity primary — light tint)
  bg-primary/20       (20% opacity primary — subtle bg)
  text-primary/70     (70% opacity primary — muted text)

Neutrals (slate, gray, white, black) are OK to hardcode.

=== global.css ===

Must include:
```css
@tailwind base;
@tailwind components;
@tailwind utilities;

:root {
  --primary: <LEAVE EMPTY — deploy system injects per-site>;
  --color-primary: <SAME AS --primary>;
  --secondary: <LEAVE EMPTY>;
  --accent: <LEAVE EMPTY>;
  --background: <LEAVE EMPTY>;
  --foreground: <LEAVE EMPTY>;
  --radius: 0.75rem;
}
```

DO NOT put real HSL values here. The deploy pipeline sets these via PUBLIC_COLORID.

=== tailwind.config.mjs ===

Must extend colors to use CSS variables:
```js
export default {
  content: ['./src/**/*.{astro,html,js,jsx,ts,tsx}'],
  theme: {
    extend: {
      colors: {
        primary: { DEFAULT: 'hsl(var(--primary) / <alpha-value>)', foreground: 'hsl(var(--foreground) / <alpha-value>)' },
        secondary: { DEFAULT: 'hsl(var(--secondary) / <alpha-value>)' },
        accent: { DEFAULT: 'hsl(var(--accent) / <alpha-value>)' },
        background: 'hsl(var(--background) / <alpha-value>)',
        foreground: 'hsl(var(--foreground) / <alpha-value>)',
      },
      borderRadius: { DEFAULT: 'var(--radius, 0.75rem)' },
    },
  },
  plugins: [],
};
```

=== Layout.astro ===

Minimal shell — tracking is injected by build pipeline:
```astro
---
import '../styles/global.css';
const { title, description } = Astro.props;
---
<!doctype html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>{title}</title>
  <meta name="description" content={description} />
  <!-- Tracking scripts injected by build pipeline -->
</head>
<body class="bg-background text-foreground antialiased">
  <slot />
</body>
</html>
```

=== INDEX.ASTRO REQUIREMENTS ===

1. Payment Calculator section:
   - Loan amount slider/buttons
   - Term selector
   - APR input
   - Monthly payment output
   - Working JavaScript calculation
   - The word "Payment Calculator" MUST appear in heading

2. Representative APR table:
   - <table> element
   - Headers: Term, APR, Example Payment
   - At least 3 rows
   - Text "Representative APR" MUST appear

3. CTA button:
   - Links to /apply (pipeline handles redirect to Voluum if configured)
   - Use bg-primary text-white for CTA styling

4. Regulatory disclosure section

5. ENV VARS — read from import.meta.env:
   PUBLIC_BRAND, PUBLIC_H1, PUBLIC_SUB, PUBLIC_CTA,
   PUBLIC_APRMIN, PUBLIC_APRMAX, PUBLIC_AMOUNTMIN, PUBLIC_AMOUNTMAX,
   PUBLIC_PHONE, PUBLIC_EMAIL

=== QUALITY GATE CHECKLIST (auto-checked on import) ===

[ ] <meta name="viewport"> with width=device-width
[ ] --primary CSS variable declaration in global.css
[ ] "Payment Calculator" section with working JS
[ ] <table> with "Representative APR" or "APR Range"
[ ] No "guaranteed approval" or "100% approval" copy (policy violation)
[ ] Uses bg-primary / text-primary NOT hardcoded colors

=== OG IMAGE (for template thumbnail in dashboard) ===

Include a static og:image URL so the dashboard shows a preview thumbnail:

GOOD (static URL — dashboard can display):
  <meta property="og:image" content="https://i.imgur.com/xxxxx.png" />

BAD (dynamic — dashboard cannot parse):
  <meta property="og:image" content={`https://${domain}/og-image.jpg`} />

Upload your og:image to Cloudflare R2, imgur, or any public CDN before importing.
If no og:image is found, the dashboard shows a gradient fallback — still works, just no preview.

=== DESIGN ===

- Mobile-first, responsive
- Dark hero or gradient hero section (use bg-primary or bg-foreground)
- Trust badges / social proof
- Sticky mobile CTA
- Google Fonts via preconnect
- Lighthouse 95+ target

=== DO NOT ===

- Do NOT hardcode colors (use bg-primary, text-primary, etc.)
- Do NOT create apply.astro (build pipeline generates it)
- Do NOT add tracking/pixel/gtag scripts (build pipeline injects them)
- Do NOT put node_modules, .git, or dist in the template
- Do NOT use "guaranteed approval", "100% approval", "free money" copy
```

## What the Build Pipeline Handles Automatically

| Concern | Handled By | When |
|---------|-----------|------|
| First-party pixel (sendBeacon) | `inject-tracking.mjs` | CI build |
| Google Ads gtag | `inject-tracking.mjs` | CI build |
| Voluum dtpCallback | `inject-tracking.mjs` | CI build |
| Click ID capture (gclid, vlcid, etc.) | `inject-tracking.mjs` | CI build |
| /apply.html (LeadsGate form) | `unified-tracking.js` → `generateApplyHtml()` | CI build |
| Color scheme (--primary, etc.) | `deploy-lp.yml` → `.env` PUBLIC_COLORID | CI build |
| Anti-fingerprint transforms | `TemplateBuilder.js` | CI build |

Template creators only need to build a beautiful landing page using `bg-primary` / `text-primary` classes.

## Quick Checklist After AI Generates Template

Before importing:

1. Does it use `bg-primary` / `text-primary` (NOT `bg-orange-500`)?
2. Does tailwind.config map primary → `hsl(var(--primary))`?
3. Does global.css declare `--primary` and `--color-primary`?
4. Is there NO apply.astro? (pipeline generates it)
5. Is there NO tracking/pixel code? (pipeline injects it)
6. Payment Calculator section present?
7. APR table present?
8. Viewport meta present?

## Import Methods

### Method 1: MCP Import (from Claude Code / Cursor)

Use the MCP tool to save template directly to database:

```
mcp__claude_ai_FusionMCP__save_template
  id: "my-template-01"
  name: "My Template"
  category: "loan"
  source_code: "<full HTML or entry file content>"
  files: { "src/pages/index.astro": "...", "src/layouts/Layout.astro": "...", ... }
```

Best for: Templates built in Claude Code, Cursor, or any MCP-connected editor.

### Method 2: CLI Upload (from local folder)

```bash
# Validate first
node scripts/validate-template-build.mjs path/to/template

# Upload to database
node scripts/folder-to-template-json.js path/to/template \
  --upload --id my-template --name "My Template" \
  --category loan --badge Bolt
```

Best for: Templates downloaded from Bolt.new or Lovable as ZIP.

### Method 3: Git Commit (local template)

Place template folder in `templates/` directory:

```
templates/
  my-template/
    package.json
    astro.config.mjs
    src/pages/index.astro
    src/layouts/Layout.astro
    src/styles/global.css
    tailwind.config.mjs
```

The template registry auto-discovers folders in `templates/`.
Best for: Templates you want version-controlled in the repo.

### Method 4: GitHub Actions CI Deploy

Push template to repo → CI builds, fingerprints, and deploys automatically via `deploy-lp.yml`.
Best for: Production deploys with full pipeline (tracking injection, anti-fingerprint, quality gate).
